# Firebase: спільна база SADOK

## Модель даних

- Firestore є спільним джерелом даних закладу.
- Локальна SQLite в IndexedDB залишається автономною копією для роботи без інтернету.
- Усі документи закладу ізольовані шляхом `organizations/{organizationId}`.
- Автоматична анонімна авторизація та автоматичне призначення ролі директора заборонені.

## 1. Firebase

1. Створіть Firebase project.
2. Увімкніть Authentication → Email/Password.
3. Створіть Firestore Database.
4. Зареєструйте Web App і скопіюйте параметри конфігурації.
5. Виберіть стабільний ідентифікатор закладу, наприклад `kzdo-145`.

## 2. Змінні середовища

Скопіюйте `.env.example` у `.env.local` для локальної роботи. У Vercel додайте ті самі змінні для Production, Preview і Development:

- `VITE_FIREBASE_API_KEY`
- `VITE_FIREBASE_AUTH_DOMAIN`
- `VITE_FIREBASE_PROJECT_ID`
- `VITE_FIREBASE_STORAGE_BUCKET`
- `VITE_FIREBASE_MESSAGING_SENDER_ID`
- `VITE_FIREBASE_APP_ID`
- `VITE_FIREBASE_ORGANIZATION_ID`

`VITE_FIREBASE_ORGANIZATION_ID` має збігатися на всіх пристроях одного закладу.

## 3. Перший керівник

Перший обліковий запис створюється один раз у Firebase Console:

1. Authentication → Users → Add user.
2. Скопіюйте UID створеного користувача.
3. У Firestore створіть документ:

```text
organizations/{organizationId}/members/{uid}
```

Поля документа:

```json
{
  "displayName": "ПІБ керівника",
  "email": "director@example.com",
  "role": "director",
  "active": true
}
```

Після входу цей керівник зможе створювати інших співробітників у панелі SADOK. Не створюйте першого директора автоматично з клієнтського застосунку.

## 4. Правила Firestore

Перед роботою з реальними даними розгорніть `firestore.rules`:

```bash
firebase login
firebase use <project-id>
firebase deploy --only firestore:rules
```

Правила ізолюють організації, дозволяють доступ лише активним учасникам і забороняють зміну журналу аудиту.

Кожна хмарна зміна сутності записується разом із відповідною подією аудиту в одній транзакції або batch-записі. Клієнт не може створити довільну подію аудиту без пов'язаної зміни сутності.

## 5. Перша синхронізація

1. Відкрийте SADOK на комп’ютері з правильною початковою базою.
2. Увійдіть обліковим записом керівника.
3. Виберіть «Спільна хмарна база + робота офлайн».
4. Натисніть «Синхронізувати зараз».
5. Дочекайтеся нульової черги та відсутності конфліктів.
6. Лише після цього підключайте інші пристрої.

Якщо хмара порожня, завантажити локальну базу може тільки директор або адміністратор. Звичайний співробітник не може випадково зробити свій пристрій початковим джерелом даних.

Початкова синхронізація має 30-хвилинну оренду. Після її завершення той самий керівник або адміністратор може відновити перерване завантаження. Віддалені записи, яких уже немає в авторитетній локальній базі, перетворюються на tombstone-записи, тому частково завантажені дані не залишаються активними.

## 6. Підключення іншого пристрою

1. Відкрийте той самий Vercel URL.
2. Увійдіть особистим обліковим записом співробітника.
3. Запустіть синхронізацію.
4. Пристрій завантажить дані своєї організації та збереже локальну автономну копію.

Не використовуйте один спільний обліковий запис для всіх співробітників: персональні облікові записи потрібні для ролей і журналу дій.
